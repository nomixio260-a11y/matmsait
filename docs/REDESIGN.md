# トピあつめ 全面改善の分析と計画（2026-10-07）

運営者の「全面改善指示書」（ニュースを記事ではなく「話題」として理解するサービスへ）を受けて、コードを変える前に現在のサイトとコードを調べた結果と、改善の計画をまとめる。実装は Phase 1 → 4 の順に進め、各 Phase の結果は `docs/DEVLOG.md` に記録する。

- 調べ方: 本番（https://topiatsume.pages.dev/ ）をスマホ（390px）・パソコン（1280px）、ライト・ダークで撮影し、速さをスマホ相当（CPU 4倍遅い・遅い回線）で測った。トピックのまとめ方の品質は、本番の記事データ（直近8日・2,801件）で、誤統合の疑いと取りこぼしの疑いを機械的に探して目で確かめた。コードは `src/lib/`・`src/pages/`・`src/components/`・`scripts/` を読んだ。
- 守ること（CLAUDE.md と指示書）: 費用のかかる AI API は使わない（AI の処理は、運営者が管理画面のプロンプトをチャット AI に貼る今の方式）。既存の機能は消さない（場所を移すことはある）。データの品質を新機能より優先する。煽る表現を使わない。

## 3. UI/UX 上の問題

1. **トップが長すぎ、最初に何を見ればよいかが分からない**: スマホで縦 15,349px（画面約18枚分）。10個の区画が同じ重さで並び、「今日の全体像」をつかむ場所がない。ファーストビューは SEO 用の見出し（「話題のニュースまとめ・ニュースランキング」）と長い説明文で、サービスの考え方が伝わらない。
2. **数字の意味が伝わりにくい**: 「話題度 56」の小さなバーと「4社が報道 ◆◆◆◆」が並ぶだけで、何の数字か・なぜその値か・「今どれだけ大きいか」と「どれだけ速く広がっているか」の違いが画面から分からない（説明は about ページの奥）。
3. **「なぜ上位なのか」が見えない**: ランキングに理由がなく、ブラックボックスに見える。
4. **急上昇の勢いが見えない**: 「3時間で+2社」のみ。何媒体から何媒体になったのか、ふだんと比べてどれだけ速いのかが分からない。
5. **カードの見た目がばらばら**: トピックの行（`TopicList`）・今日の重要（`ImportantList`）・記事の行（`ItemRow`）・要約のカード（`SummaryCard`）で、数字・時間・出典の位置と表現が違う。
6. **絵文字のアイコン**（🔥🚀📰🔎🤖📊）: 環境で見た目が変わり、色の意味づけもない。
7. **ナビが多すぎる**: ヘッダーのタブが14個（総合・話題・急上昇・AIニュース・AI要約・カテゴリ9個）で、スマホでは横スクロール。主要な行き先が埋もれる。
8. **新着が記事の羅列**: トップの新着20件（抜粋つき）が縦に長い。
9. **トピックページの情報の順番**: 大事な「なぜ話題か」「各社の違い」がなく、報道の一覧が抜粋つきで長い。タイムライン・広がり・推移が1つのグラフに混ざっている。

## 4. 情報設計上の問題

- 「今なにが起きている？（今話題）」「急に何が起きた？（急上昇）」「今日何を知ればいい？（今日の注目）」「何が変化している？（注目ワード・トレンド）」「詳しく知りたい（トピック）」という問いの順に画面が組まれていない。
- 「昨日と比べて何が変わったか」を示す場所がない（日別まとめも記事の一覧で、分析になっていない）。
- 注目ワードはチップの羅列で、出現数・ふだんとの比・関連トピックが見えない。言葉から探索する先（キーワードのページ）がない。
- AI ニュース・AI 要約・メディア別・よく読まれている記事がトップで同じ重さで並び、主要な体験（トピック）の邪魔をしている。

## 5. ブランド上の問題

- キャッチコピー（「いま何が話題か、一瞬でわかる。」）はスマホでは表示されず、トップの見出しは SEO の言葉。「ニュースを話題で読む」という考え方が画面のどこにもない。
- 用語がそろっていない: 同じものを「話題」「話題のニュース」「ニュース」「記事」と呼び、報じた数を「◯社」（同じ会社の別媒体も別に数えているので不正確）と書いている。
- 「今日の重要ニュース」の「重要」に定義がない（実際は「多くの媒体が報じ、ジャンルが広い」）。指示書のとおり、話題と重要を混同させない言葉が要る。
- AI が前面に出ている（「AI要約」のバッジが多い）。価値は「10秒で把握・30秒で理解・2分で深掘り」で、AI は裏側の技術として扱いたい。

## 6. 差別化上の問題

- トピック化・話題度・急上昇・初報・報道の一覧という土台はあるが、**「同じニュースを各社がどう報じたか」（共通点・強調点の違い・数字の食い違い）が出せていない**。今の AI 要約は記事1本ずつの形式で、比較の整理をする仕組みがない。
- 「変化」（昨日比・急に現れた言葉・言葉の組み合わせ・ジャンルの増減）を見せる機能がない。
- 人物・企業・キーワードから辿る探索の入口がない（タグ13個だけ）。
- 結果として、見た目は「ランキングのあるニュースまとめ」に近く、初めて来た人に違いが伝わりにくい。

## 7. クラスタリング・データ品質上の問題

本番の記事データで調べた結果:

- **誤統合はほぼない**: 2媒体以上のトピック 87件（3媒体以上 21件）で、「トピック内のほかのどの記事とも似ていない記事」（鎖のようにつながった誤統合の疑い）は 0件。見出しがよく似ていても分かれていた6組は、別々の行事の「高市総理ビデオメッセージ」など、正しく分けられていた。
- **取りこぼしが多い**: 別々の媒体の記事で、珍しい固有名詞（カタカナ・英数字3文字以上）を2つ以上共有しているのに別のトピックになっている組が、3日間で89組。目で確かめると半分ほどは同じ出来事だった（例: サンソフト『リップルアイランド』のコンソールアーカイブス配信（4媒体がばらばら）、日本ファルコム『軌跡』1000万本、Movable Type の脆弱性、Razer Wolverine V4、ジープ新型コンパス、VRChat の AI 方針、ポケモンホームの GBA 連携）。残りは同じ固有名詞を含む別の出来事（フェラーリの別々の特別仕様、同じゲームのドライバー対応と発売、別々のインタビュー）で、**固有名詞だけでまとめると誤統合になる**。
- 原因: 見出しの言い回しが大きく違う（長い見出し・記号・説明の付け足し）と、2文字の組の似かたが閾値（0.33）に届かない。
- 手で直す手段がない（統合・分割）。トピックの URL は「最初の記事の ID」なので、あとから早い記事がつながると変わる（まれ）。
- 日別まとめの同じ話題の重複は 2026-10-07 に解消済み。

## 8. SEO 上の問題

- トピックページの題名が長すぎる（見出し全文＋「｜4社の報道まとめ｜トピあつめ」）。検索結果では後半が切れ、トピあつめ独自の情報（媒体数・比較）が見えない。
- 独自データ（話題度・急上昇・初報・タイムライン・媒体比較・推移）がページの本文として十分に書かれていない（数字とグラフだけ）。
- 内部リンクが「記事 → トピック」「トピック → タグ」まで。キーワード・過去のトピックへのリンクがない。
- 日別まとめが記事の一覧で、その日の分析（独自の内容）になっていない。
- 検索用データ（`search-index.json`）が 1.3MB（圧縮後 476KB）で、スマホの検索ページが重い（SEO より体験の問題）。

## 9. パフォーマンス上の問題

- 速さは良好: スマホ相当でトップの LCP 1.6秒・CLS 0、トピックページ 0.9秒・CLS 0。JS はトップで 18KB。
- 気をつける点: トップの HTML 192KB（転送 25KB）・DOM 1,847要素は、長すぎるトップが原因。区画を絞れば軽くなる。検索用データ 1.3MB は、トピックの索引と記事の索引に分けて、必要になってから読む形にしたい。
- 毎時のビルドは約5秒。機能を足してもビルドを30秒以内に保つ（「今すぐ投稿」の速さにも響く）。

## 12. 実装の順序

### Phase 1: ブランド・UI
1. デザインの土台: 意味に結びつけた色（🔥話題度・🚀急上昇・⏱時間/初報・📰報道数・🔤キーワード。色は大事な数字だけ）、文字の大きさと太さの段階（話題度の数字を特徴的な書体に）、余白、ダークモードの階層、SVG アイコン（絵文字を置き換える）。
2. 用語: 単位は「トピック」、報じた数は「◯媒体」、話題度＝「今どれくらい話題か」、急上昇＝「どれくらいの速さで広がっているか」、初報＝「最初に確認できた報道」、「今日の重要」→「今日の注目」（定義つき）。
3. トピックのカードを1つに: 題名・状態（急上昇中・NEW）・数字（話題度とメーター・媒体数・3時間の増加）・時間・出典・「なぜ話題？」の1行・「なぜこの話題度？」の内訳（開くと見える）。
4. 急上昇の勢い: 「2媒体 → 7媒体」「+5媒体/3時間」「ふだん（直前6時間）の◯倍の速さ」。
5. トップの再設計: ファーストビュー（ロゴ・コピー・今日の状態・CTA）→ 今日のトピあつめ（TODAY の数）→ 今日のニュース温度（ジャンルごと）→ 今日、変化したこと → 今話題 → 急上昇 → 今日の5トピック → 注目ワード → 新着（時刻のタイムライン）。AI ニュース・10秒でわかるニュース・メディア別・カテゴリ別は、それぞれのページ（`/tag/ai/`・`/summaries/`・`/sources/`・新しい `/genres/`）へ移す（消さない）。
6. ナビ: 主要5つ（ホーム・話題・急上昇・トレンド・ジャンル）＋検索・フォロー・あとで読む・テーマのアイコン。カテゴリ・AI ニュース・AI 要約は「ジャンル」から。
7. 共有画像・about（用語と計算のしかた）・Bluesky の投稿文の言葉をそろえる。

### Phase 2: トピックの体験
1. トピックページの構成: 題名・状態・話題度（なぜこの値か）・急上昇・媒体数・初報（「最初に確認できた報道」）→ 💡なぜ話題？ → 10秒で把握／30秒で理解／2分で深掘り → 各メディアの視点（AI 整理。なければ見出しの違いを機械的に比べて表示）→ 報道タイムライン → 報道の広がり（1→3→7媒体）→ 話題度の推移とライフサイクル（発生・拡大・ピーク・減少）→ 背景 → 関連（キーワード・タグ・関連トピック・過去の似たトピック）。高度な情報は折りたたむ。
2. AI 整理（運営者がチャット AI で作る）: 管理画面に「トピック整理」のプロンプトを追加（同じトピックの各媒体の記事をまとめて渡す）。回答は「共通して報じられていること（出典つき）」「各社が特に強調していること」「報道内容の差（どちらが正しいかは決めない）」「背景」「AI による整理・解釈（事実と分けて表示）」。出典はトピックの媒体に限り、煽る言葉は検証で弾く。
3. SEO: 題名を「（見出しの要点）｜◯媒体の報道を比較」に短く、独自データを本文として書く。

### Phase 3: 探索
1. トピックのまとめ方: 固有名詞・数字・日付を手がかりにした2段目のまとめ（取りこぼしを減らす。ただし固有名詞だけでは結ばない）。本番データから作った「同じ／別」の組をテストにして、誤統合を増やさないことを確かめる。管理画面でトピックを統合・分割できるようにする（`data/topic-overrides.json`）。
2. キーワードのページ（人物・企業・製品・テーマ）: 現在の話題度・7日間の推移・今日のトピック・関連キーワード（一緒に出てくる言葉）・関連タグ。
3. 検索: 結果をトピック・キーワード・記事に分ける。「今日 急上昇 AI」のような言葉を解釈して絞り込み、「なぜこの結果か」を表示する。索引を分けて軽くする。
4. 内部リンク: 記事 → トピック → キーワード → 過去のトピック。

### Phase 4: トレンド
1. 日ごとの集計を残す（`data/trends/`。ジャンル別のトピック数・言葉の出現数・上位トピック）。今は記事が約10日分しか残らないため。
2. トレンドのページ: 注目ワード（今日の数・7日平均・増加率・関連トピック）、急に現れた言葉、一緒に出始めた言葉の組み合わせ、ジャンルの変化（昨日比）、昨日との違い（急増・急減・新登場・収束）。
3. 今週のトピあつめ（週間）と、日別まとめを「その日の分析」に。

## 13. データ構造の改善案

- `data/topic-notes/YYYY-MM.json`: AI 整理（トピックの記事 ID の組で保存。トピックの ID が変わっても結び付けられる）。
- `data/topic-overrides.json`: 運営者による統合（記事 ID の組）・分割（トピックから外す記事 ID）。
- `data/trends/YYYY-MM-DD.json`: その日の集計（ジャンルごとのトピック数・報道数、言葉の出現数、上位トピック）。長い期間のトレンド・週間・月間に使う。
- 記事ごとの要約（`data/summaries/`）はそのまま使い、キーワードを人物・企業などに分けるのは任意の項目として追加する。

## 14. 技術的なリスクと対策

- **AI 整理は運営者の手作業**（有料 API を使わないため）: 整理のないトピックが多い。→ 整理がなくても「見出しの違い」「タイムライン」「なぜ話題」を機械的に出せるようにし、AI 整理は上乗せにする。
- **まとめ方を変えるとトピックの ID（URL）や数字が変わる**: → 本番データの組でテストし、誤統合が増えないことを確かめてから入れる。統合・分割の手動の修正で補う。
- **記事が約10日分しか残らない**: → 日ごとの集計を残す（Phase 4）。
- **ナビからカテゴリのタブを外す影響**（カテゴリのページへの回遊）: → 「ジャンル」の入口・サイドバー・フッターから辿れるようにし、アクセス解析で確かめる。
- **ビルド時間**: 計算を足すたびに測り、30秒以内に保つ。

## 15. やらないこと（理由）

- 有料の AI API（運営者の方針）、外部の埋め込み（embedding）API（有料）。端末で動く機械学習モデルも、毎時のビルドが遅くなりデータが大きくなるので今は使わない（固有名詞・数字・日付のルールと、手動の統合・分割で品質を上げる）。
- 大量の記事のフィード・おすすめのパーソナライズ（SmartNews の小型版にしない）。
- 「衝撃」「ヤバい」「大炎上」「必見」のような煽る表現（AI の文章も検証で弾く）。
- 記事本文の転載（見出し・短い抜粋・リンク・独自の数字と整理だけを載せる）。
